## Alpha test completion rule

Use the included `docs/alpha-feedback-form.html` with real volunteer testers. Aim for 5–10 students from the intended user groups, but report the actual count. Do not fabricate feedback. Remove any accidental personal information before including feedback in the report. Summarize ratings as counts/averages and summarize free-text themes without identifying respondents.

The recommendation algorithm is considered refined only when there is a documented evidence chain:

1. Feedback observation (with anonymized count and example theme).
2. Product/algorithm decision (change or retain, with reason).
3. Regression test or formula check.
4. Before/after comparison on the same sample data, if the formula changed.

## Submission wording

Use “44 backend tests passed” for the developer-provided result. Use “repeatable local synthetic-data load tests performed” only after the new suite has completed successfully. Do not claim production-scale readiness or a quantified optimization unless repeated measurements support it. If alpha feedback has not been collected by submission, mark it as a next validation step rather than claiming completion.
